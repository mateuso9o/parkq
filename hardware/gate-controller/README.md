# ParkQ Gate Controller – คู่มือสร้างและอธิบายวงจร

บอร์ดนี้คือ "สมอง" ของโมเดลลานจอด ParkQ (LOT02) ใช้ ESP32 DevKit 1 ตัว คุมสิ่งเหล่านี้:

- เครื่องอ่าน QR 2 ตัว (ขาเข้า / ขาออก)
- เซอร์โวไม้กั้น 2 ตัว (SG90)
- เซนเซอร์ IR ตรวจช่องจอด 4 ช่อง
- LED เขียว / แดง, LED แสดงไฟเข้า, บัซเซอร์

คู่มือนี้มี 3 ส่วน: **สร้างบอร์ด** (หัวข้อ 1–4) → **อธิบายวงจร** (หัวข้อ 5–6) → **ลงเฟิร์มแวร์** (หัวข้อ 7)

ศัพท์เทคนิคจะมีภาษาอังกฤษในวงเล็บเมื่อพูดถึงครั้งแรก

---

## 0. ทำก่อนสั่งของ (สำคัญมาก)

**วัดระยะห่างระหว่างแถวขา (row spacing) ของ DevKit ที่ซื้อมาจริง ก่อนสั่งบอร์ด**

DevKit 30 ขามี 2 แบบ:

| แบบ | ระยะห่างแถวขา (วัดจากกึ่งกลางรูถึงกึ่งกลางรู) |
|---|---|
| ส่วนใหญ่ (DOIT V1) | 25.4 mm (1.0 นิ้ว) |
| บางรุ่น | 22.86 mm (0.9 นิ้ว) |

ไฟล์บอร์ดตั้งไว้ที่ **25.4 mm** ถ้าของคุณเป็น 22.86 mm:

1. เปิดไฟล์ `hardware/gate-controller/design.py`
2. แก้บรรทัด `DEVKIT_ROW_PITCH_MM = 25.4` เป็น `22.86`
3. รัน `python hardware/gate-controller/build_all.py` ใหม่
4. ใช้ไฟล์ ZIP ใหม่ในโฟลเดอร์ `build/`

ถ้าไม่วัดก่อน DevKit จะเสียบบอร์ดไม่ลง และต้องสั่งบอร์ดใหม่

## 1. สร้างไฟล์ แล้วนำเข้า EasyEDA Standard

### 1.1 สร้างไฟล์

ต้องมี Python 3 (ไม่ต้องลงไลบรารีเพิ่ม) รันจากโฟลเดอร์หลักของโปรเจกต์:

```
python hardware/gate-controller/build_all.py
```

จะได้ 3 ไฟล์ในโฟลเดอร์ `hardware/gate-controller/build/`:

- `ParkQ_Gate_SCH.zip` – แผนผังวงจร (schematic) พร้อมไลบรารีสัญลักษณ์
- `ParkQ_Gate_PCB.zip` – แผ่นปริ้นท์ (PCB) อย่างเดียว
- `ParkQ_Gate_layout.png` – รูปแสดงตำแหน่งชิ้นส่วน

โฟลเดอร์ `build/` ไม่ถูกเก็บใน git ต้องรันคำสั่งข้างบนเองก่อนจึงจะมีไฟล์ รูปด้านล่างจะขึ้นหลังรันแล้วเท่านั้น

![ตำแหน่งชิ้นส่วนบนบอร์ด](build/ParkQ_Gate_layout.png)

### 1.2 นำเข้า (Import)

ใช้ **EasyEDA Standard** (https://easyeda.com/editor) ไม่ใช่ Pro ไฟล์ของเราเป็นรูปแบบ KiCad รุ่นเก่า (5.0) เพราะ EasyEDA รับ KiCad 4.06 ขึ้นไป

**แผนผังวงจร (Schematic)**

1. สร้างโปรเจกต์ใหม่ (File → New → Project)
2. File → Import → KiCad (หรือ Import KiCad)
3. เลือก `ParkQ_Gate_SCH.zip` (ไฟล์วงจรกับไลบรารีอยู่ใน ZIP เดียวกันอยู่แล้ว ห้ามแยก)
4. ตรวจว่าชิ้นส่วนครบ และเส้นต่อ (net) ถูก

หมายเหตุ: สัญลักษณ์ไฟ (+5V, GND, +3V3) จะกลายเป็นสัญลักษณ์ธรรมดา ไม่ใช่สัญลักษณ์ไฟของ EasyEDA ไม่ต้องตกใจ ถ้า net ยังต่อกันตามชื่อก็ใช้ได้

**แผ่นปริ้นท์ (PCB)**

1. File → Import → KiCad
2. เลือก `ParkQ_Gate_PCB.zip` (ZIP นี้ใส่ไฟล์ PCB อย่างเดียว)
3. ตรวจรูปร่างบอร์ด 80 × 70 mm และตำแหน่งชิ้นส่วนให้ตรงกับรูป `ParkQ_Gate_layout.png`

สิ่งที่ต้องรู้หลัง import:

- **กฎการออกแบบ (design rules) ไม่ถูกนำเข้า** ต้องตั้งเองตามหัวข้อ 2
- **พื้นทองแดง (copper area)** จะถูกสร้างใหม่หลัง import ให้ตรวจดูอีกครั้ง
- **รูเจาะแบบยาว (slot)** ของแจ็คไฟ DC (3 รู) อาจหาย ถ้าหายหรือกลายเป็นรูกลมเล็ก ให้แก้รูทั้ง 3 เป็น **รูกลมขนาด 3 mm ขึ้นไป** หรือวาด slot เองในเลเยอร์ Hole/Multi
- **ยังไม่มีเส้นทองแดง (track)** บอร์ดนี้ยังไม่ได้ลากสายเลย ใช้ Auto Router ตามหัวข้อ 2

## 2. ลากสาย (Auto Router) และตรวจ (DRC)

ใน PCB Editor เลือก Route → Auto Router แล้วตั้งค่า:

| ค่า | ตั้งเป็น |
|---|---|
| ความกว้างสายสัญญาณ (track width) | 0.3 mm |
| ความกว้างสายไฟ `+5V`, `GND`, `VIN_RAW`, `VIN_FUSED` | 1.0 mm |
| ระยะห่าง (clearance) | 0.25 mm |
| จำนวนชั้นทองแดง (layers) | 2 (Top + Bottom) |

ทำตามนี้:

1. ตั้ง Design Rules ก่อน (Design → Design Manager → Net Rule) ใส่ 1.0 mm ให้ 4 net ไฟข้างบน
2. รัน Auto Router จนลากครบ (ถ้าเหลือเส้นที่ลากไม่ได้ ให้ย้ายชิ้นส่วนนิดหน่อยหรือลากเอง)
3. สร้างพื้น GND (Copper Area) ที่ Bottom แล้ว **Rebuild Copper Area** (Tools → Rebuild Copper Area)
4. รัน **Design Rule Check (DRC)** ต้องไม่มี error ถ้ามีให้แก้จนหมด
5. ตรวจดูด้วยตาอีกรอบ โดยเฉพาะรอบแจ็คไฟและใต้ DevKit

ทำไมสายไฟต้องกว้าง 1.0 mm: เซอร์โวดึงกระแสสูงชั่วคราว (หลายร้อย mA) สายเล็กจะร้อนและแรงดันตก

## 3. สั่งบอร์ดที่ JLCPCB

ใน EasyEDA: Fabrication Output → Gerber → Order at JLCPCB แล้วเลือก:

| ตัวเลือก | ค่า |
|---|---|
| Layers | 2 |
| PCB Thickness | 1.6 mm |
| Surface Finish | HASL (with lead ก็ได้ ถูกกว่า) |
| จำนวน (Quantity) | 5 แผ่น |
| ขนาด | 80 × 70 mm |

ราคาโดยประมาณ: บอร์ดประมาณ 2 USD (ราคาโปรโมชั่นแผ่นเล็ก) ค่าส่งเพิ่มอีกหลายเท่า (ประมาณ 10–20 USD ขึ้นกับวิธีส่ง) ตัวเลขนี้เป็น **การประมาณ** ราคาจริงดูหน้าสั่งซื้อ ใช้เวลาผลิต 2–4 วัน ส่งมาไทยประมาณ 1–2 สัปดาห์

อย่าเลือกบริการประกอบ (SMT assembly) เพราะบอร์ดนี้ใช้ชิ้นส่วนแบบมีขา (through-hole) ทั้งหมด เราบัดกรีเอง

## 4. รายการชิ้นส่วน (BOM) และการบัดกรี

ราคาเป็น **บาทโดยประมาณ** (ร้านไทยเปลี่ยนตามช่วงเวลา) รหัส LCSC ใส่เฉพาะที่ค้นเจอหน้าสินค้าจริงใน LCSC ส่วนที่ไม่ได้ยืนยัน ให้ค้นตามคำที่ระบุ (ผู้ผลิตแต่ละเจ้ามีหลายรหัส เลือกที่เป็นแบบ through-hole/DIP)

ชื่อค้นร้านไทยที่ใช้ได้: ร้านอิเล็กทรอนิกส์ออนไลน์ทั่วไป เช่น ร้านขายส่วนประกอบใน Shopee/Lazada, ร้านใน ETT, Arduino-Thai หรือร้านแถวสะพานเหล็ก

### 4.1 ไฟเข้าและป้องกัน

| อ้างอิง | จำนวน | ค่า | ค้นร้านไทยว่า | LCSC | ราคาโดยประมาณ |
|---|---|---|---|---|---|
| J_PWR | 1 | แจ็ค DC 5.5×2.1 | "DC jack 5.5x2.1 ตัวเมีย แบบเสียบแผ่นปริ้นท์" | ค้นใน LCSC: `DC-005 5.5x2.1 DC power jack through hole` | 5–10 |
| F1 | 1 | PTC 2A (ฟิวส์รีเซ็ตเองได้) | "PTC 2A รีเซ็ตฟิวส์ แบบขา (radial)" | ค้นใน LCSC: `PTC resettable fuse radial 2A 6V` (หาแบบขายาว through-hole) | 5–10 |
| D1 | 1 | 1N5822 (ชอตกี 3A 40V) | "1N5822 diode" | **C84619** (Changzhou Starsea) | 3–5 |
| C1 | 1 | 470 µF 16 V (ขั้ว +/-) | "คาปาซิเตอร์ 470uF 16V" | **C432444** (Rubycon 16YXJ470M8X11.5) | 3–5 |
| C2 | 1 | 100 nF (เซรามิก) | "คาปาซิเตอร์เซรามิก 104 100nF" | ค้นใน LCSC: `100nF 50V ceramic capacitor through hole 5mm` | 1 |

**ทำไม D1 เป็น 1N5822 ไม่ใช่ SS34:** SS34 เป็นแบบติดผิว (SMD) บัดกรีลงรูไม่ได้ บอร์ดนี้ใช้ชิ้นส่วนแบบมีขาทั้งหมด จึงใช้ 1N5822 ซึ่งเป็นไดโอดชอตกีเบอร์เดียวกัน (3 A 40 V) แบบมีขา (ตัวถัง DO-201AD) หน้าที่เหมือนกัน

### 4.3 ตัวต้านทาน (resistor) 1/4 W

| อ้างอิง | จำนวน | ค่า | หน้าที่ | ค้นร้านไทยว่า | LCSC |
|---|---|---|---|---|---|
| R1, R2, R3, R4, R10 | 5 | 1 kΩ | R1–R4 อนุกรมสาย UART ของ QR, R10 ฐานทรานซิสเตอร์ | "ตัวต้านทาน 1k 1/4W" | ค้นใน LCSC: `1kΩ 1/4W carbon film through hole` |
| R5, R6 | 2 | 2 kΩ **(DNP – ไม่ต้องใส่)** | ตัวแบ่งแรงดัน ใส่เฉพาะเมื่อ QR ส่ง 5 V | "ตัวต้านทาน 2k 1/4W" | ค้นใน LCSC: `2kΩ 1/4W carbon film through hole` |
| R7, R8, R9 | 3 | 330 Ω | จำกัดกระแส LED | "ตัวต้านทาน 330 โอห์ม 1/4W" | ค้นใน LCSC: `330Ω 1/4W carbon film through hole` |

ราคาตัวละประมาณ 0.5 บาท (ซื้อเป็นชุดมีหลายค่าคุ้มกว่า) **DNP = Do Not Populate คือเว้นไว้ ไม่บัดกรี** R5/R6 ให้ซื้อมาสำรองแต่ยังไม่ใส่ (ดูหัวข้อ 5.3)

### 4.5 สิ่งที่ต้องซื้อเพิ่มนอกบอร์ด

| รายการ | จำนวน | หมายเหตุ | ราคาโดยประมาณ |
|---|---|---|---|
| Adapter 5 V 2 A (หัวแจ็ค 5.5×2.1 ขั้วกลางเป็น +) | 1 | ดูหัวข้อ 5.1 ว่าทำไมต้องใช้ Adapter | 100–150 |
| เซอร์โว SG90 | 2 | ไม้กั้นขาเข้า/ออก | 40–60 ต่อตัว |
| เครื่องอ่าน QR (GM65 / GM861 แบบ UART) | 2 | ตั้ง baud 9600 | 250–500 ต่อตัว |
| โมดูล IR slot sensor (3 ขา: VCC, GND, OUT) | 4 | ตัวตรวจรถแต่ละช่อง | 15–30 ต่อตัว |
| สายจัมเปอร์ตัวเมีย-ตัวเมีย | 1 ชุด | ต่อโมดูลเข้า header | 30–50 |

ราคารวมทั้งโปรเจกต์อยู่ที่ประมาณ 1,000–1,800 บาท (ประมาณการ)

### 4.6 ข้อควรระวังตอนบัดกรี

1. **บัดกรีของเตี้ยก่อน ของสูงทีหลัง:** ตัวต้านทาน/ไดโอด → female header → ตัวเก็บประจุ → แจ็ค
2. **ไดโอดมีทิศทาง:** ด้านที่มีแถบสีขาว/เทา = ขา K (cathode) ตรงกับเส้นบนซิลค์สกรีน
   - D1: แถบหันไปทาง +5V (ไปทาง C1)
   - D2: แถบหันไปทาง +5V
3. **C1 (470 µF) มีขั้ว:** ขายาว = +, ขาสั้น (แถบสีบนตัว) = − ถ้าใส่กลับด้านอาจระเบิดได้
4. **S8050 (Q1):** ขา TO-92 ห่าง 1.27 mm แต่รูบนบอร์ดห่าง 2.54 mm ให้ **งอขาออกนิดหน่อย** ก่อนใส่ ด้านเรียบ (flat) หันตามซิลค์สกรีน ขาเรียง E–B–C (ดู datasheet ของยี่ห้อที่ซื้อ บางยี่ห้อเรียงต่างกัน)
5. **LED:** ขายาว = ขา **A (anode)** อยู่ที่ **pad 2** ส่วน **pad 1 = cathode** (ด้านแบนของตัว LED) ใส่กลับ LED จะไม่ติดแต่ไม่พัง
6. **R5, R6: ไม่ต้องบัดกรี** (DNP)
7. **อย่าเพิ่งเสียบ DevKit** จนกว่าจะวัดไฟ: ต่อ Adapter แล้ววัดที่ขา VIN ของซ็อกเก็ต ควรได้ประมาณ 4.5–4.8 V (5 V ลบแรงดันตกคร่อม D1 ประมาณ 0.3–0.5 V) และ LED3 ต้องติด
8. **ห้ามจ่ายไฟเซอร์โวจาก USB อย่างเดียว** USB จ่ายกระแสไม่พอ ESP32 จะรีเซ็ตซ้ำๆ ให้ใช้ Adapter 5 V เสมอเมื่อต่อเซอร์โว

## 5. อธิบายวงจรทีละบล็อก (เตรียมตอบอาจารย์)

ภาพรวม: ไฟ 5 V จาก Adapter → ป้องกัน → ราง +5V → จ่าย DevKit (ทางขา VIN) และเซอร์โว/QR/บัซเซอร์ ส่วน 3.3 V จาก DevKit จ่ายเซนเซอร์ IR

### 5.1 บล็อกไฟเข้า (Power)

```
DC Jack → F1 (PTC 2A) → D1 (1N5822) → ราง +5V → DevKit VIN
                                          ├── C1 470µF + C2 100nF → GND
                                          ├── เซอร์โว 2 ตัว
                                          ├── QR 2 ตัว
                                          └── บัซเซอร์, LED3
```

- **J_PWR** รับไฟ 5 V จาก Adapter ขา 1 = tip (+), ขา 2 = sleeve (−)
- **F1 (PTC fuse)** ฟิวส์รีเซ็ตเอง ถ้าลัดวงจรหรือดึงกระแสเกิน มันจะร้อนและความต้านทานสูงขึ้นจนตัดไฟ พอเย็นก็กลับมาใช้ได้ ไม่ต้องเปลี่ยน
- **D1 (1N5822)** กันขั้วกลับ (reverse polarity protection) ถ้าเสียบ Adapter ผิดขั้ว ไดโอดจะไม่ให้กระแสไหลเข้า วงจรไม่พัง เลือกชอตกีเพราะแรงดันตกคร่อมต่ำ (ประมาณ 0.3–0.5 V) เมื่อเทียบกับไดโอดธรรมดาที่ตก 0.7 V ขึ้นไป
- **C1 470 µF** ตัวเก็บประจุก้อนใหญ่ ทำหน้าที่เหมือน "ถังน้ำสำรอง" ตอนเซอร์โวออกตัวจะดึงกระแสพุ่งสูงชั่วขณะ ราง 5 V จะตก ถ้าไม่มี C1 ESP32 จะ brown-out (แรงดันตกจนรีเซ็ต)
- **C2 100 nF** กรองสัญญาณรบกวนความถี่สูง

**ทำไมใช้ Adapter ไม่ใช้ USB:** เซอร์โว SG90 แต่ละตัวดึงกระแสได้หลายร้อย mA ตอนขยับ (ตอนติดขัดได้เกือบ 700 mA) รวมกับ QR 2 ตัว USB จากคอมพิวเตอร์จ่ายประมาณ 500 mA เท่านั้น จึงไม่พอ ผลคือบอร์ดรีเซ็ต Wi-Fi หลุด Adapter 5 V 2 A จ่ายพอ USB ใช้เฉพาะตอนลงเฟิร์มแวร์และดู Serial Monitor ตอนทดสอบเซอร์โวควรใช้ Adapter ด้วย

**ทำไมไม่จ่ายไฟมากกว่า 5 V:** เซอร์โวและ QR ต้องการ 5 V ราง +5V ใช้ร่วมกันทั้งหมด

### 5.2 บล็อกเซนเซอร์ IR (3.3 V)

- J_SLOT1–4 ขา 1 = **+3V3**, ขา 2 = GND, ขา 3 = OUT ต่อเข้า GPIO34, 35, 36, 39
- **ทำไมจ่าย 3.3 V ให้เซนเซอร์:** ขา GPIO ของ ESP32 **ทนแรงดัน 5 V ไม่ได้** (ทนได้ 3.3 V) ถ้าจ่ายเซนเซอร์ 5 V ขา OUT อาจออกมา 5 V แล้วทำ ESP32 เสียหาย จ่าย 3.3 V ขา OUT จึงไม่เกิน 3.3 V แน่นอน
- **GPIO34–39 เป็น input-only:** ขาเหล่านี้ใช้เป็นอินพุตอย่างเดียว (ส่งสัญญาณออกไม่ได้) และไม่มี pull-up/pull-down ภายใน เหมาะกับเซนเซอร์ที่ขับเส้นสัญญาณเอง จึงใช้ขาเหล่านี้กับ 4 ช่องจอด
- เฟิร์มแวร์: LOW = มีรถ (โมดูล IR ส่วนใหญ่ดึง OUT ลงเมื่อเจอวัตถุ) ถ้าโมดูลที่ซื้อกลับขั้ว ให้แก้เงื่อนไขใน `checkSlots()` ของ `main.cpp`

### 5.3 บล็อกเครื่องอ่าน QR (UART)

QR reader สื่อสารแบบ UART (อนุกรม) 2 เส้น: TX กับ RX โดย TX ของเครื่องอ่านต่อเข้า RX ของ ESP32 (ไขว้กัน)

| เครื่องอ่าน | ESP32 RX | ESP32 TX |
|---|---|---|
| ขาเข้า (IN) | GPIO16 | GPIO17 |
| ขาออก (OUT) | GPIO32 | GPIO33 |

- **R1–R4 (1 kΩ อนุกรม):** วางไว้ระหว่างเครื่องอ่านกับ ESP32 ทั้ง 2 ทิศ เป็นตัวป้องกัน ถ้าต่อสายผิดหรือ TX ชนกับ TX กระแสจะถูกจำกัดไว้ไม่ทำให้ขา GPIO พัง
- **R5, R6 (2 kΩ, DNP):** ตัวแบ่งแรงดัน (voltage divider) ใส่ **เฉพาะเมื่อ TX ของเครื่องอ่านส่งสัญญาณ 5 V** โมดูล GM65/GM861 ส่วนใหญ่เป็นลอจิก 3.3 V อยู่แล้ว (ไม่ต้องใส่) ให้วัดสัญญาณ TX ของเครื่องอ่านที่ซื้อมาก่อน

  คำนวณ: R1 (1 kΩ) อนุกรม + R5 (2 kΩ) ลง GND

  `V_RX = 5 V × 2 kΩ / (1 kΩ + 2 kΩ) = 3.33 V`

  ซึ่งปลอดภัยสำหรับ ESP32 (ทนได้ 3.3 V)
- **ทำไม GPIO32/33 สำหรับ QR OUT:** ESP32 มี UART ฮาร์ดแวร์ 3 ชุด UART0 ใช้กับ USB (ลงเฟิร์มแวร์/Serial Monitor) UART2 ใช้ GPIO16/17 สำหรับ QR IN ส่วน QR OUT ใช้ UART1 ที่ย้ายขา (remap) ไปที่ GPIO32/33 เพราะขา default ของ UART1 ไปชนกับ flash
- ตั้งค่า baud ที่ 9600 (ค่าใน `config.example.h`)

### 5.4 บล็อกเซอร์โว (Servo)

- สัญญาณ PWM (Pulse Width Modulation) จาก **GPIO18 (ขาเข้า)** และ **GPIO19 (ขาออก)** ขากว้างพัลส์ประมาณ 1–2 ms บอกมุม (เฟิร์มแวร์ใช้ 0° = ปิด, 90° = เปิด)
- ไฟของเซอร์โวมาจากราง **+5V แยกต่างหาก** ไม่ได้ผ่านขา 3V3 ของ DevKit เพราะเซอร์โวกินกระแสเยอะเกินกว่าที่ regulator บน DevKit จะจ่ายไหว
- ขา header: 1 = GND, 2 = +5V, 3 = สัญญาณ (ตรงกับสีสายเซอร์โว: น้ำตาล/แดง/ส้ม)
- ใช้คลาส `ESP32Servo` เพราะ PWM ของ ESP32 ไม่ใช่ `Servo.h` ของ Arduino UNO

### 5.5 บล็อกบัซเซอร์ (Buzzer driver)

```
GPIO4 → R10 (1k) → ฐาน Q1 (S8050)
บัซเซอร์: +5V → BZ1 → คอลเลคเตอร์ Q1 → อิมิตเตอร์ → GND
D2 (1N4148) คร่อมบัซเซอร์ (cathode ที่ +5V) = flyback diode
```

- **ทำไมต้องมีทรานซิสเตอร์:** GPIO ของ ESP32 จ่ายกระแสได้ประมาณ 12–20 mA ต่อขา บัซเซอร์ 5 V ใช้ประมาณ 30 mA และต้องใช้ไฟ 5 V ทรานซิสเตอร์ทำหน้าที่เป็นสวิตช์: GPIO ให้กระแสฐานเล็กๆ ไปเปิดให้กระแสใหญ่ไหลผ่านบัซเซอร์
- **กระแสฐาน:** (3.3 V − 0.7 V) / 1 kΩ ≈ 2.6 mA เพียงพอให้ S8050 อิ่มตัว (รับกระแสได้ถึง 500 mA)
- **D2 flyback diode:** บัซเซอร์เป็นโหลดแบบขดลวด (inductive) เมื่อปิดสวิตช์ ขดลวดจะสร้างแรงดันสูงย้อนกลับ (voltage spike) ที่ทำลายทรานซิสเตอร์ได้ ไดโอดช่วยให้กระแสวนกลับ แรงดันพุ่งจึงไม่เกิดขึ้น
- เฟิร์มแวร์: HIGH = ดัง (สั้น 150 ms เมื่อผ่าน, ยาว 800 ms เมื่อไม่ผ่าน)

### 5.6 บล็อก LED

- **LED1 เขียว (GPIO23), LED2 แดง (GPIO22):** GPIO → R (330 Ω) → LED → GND
- **LED3:** ไฟแสดงว่ามีไฟเข้า +5V → R9 (330 Ω) → LED → GND (ไม่ผ่าน ESP32)
- ทำไมต้องมีตัวต้านทาน: LED ไม่จำกัดกระแสเอง ถ้าไม่ใส่จะกินกระแสมากจน LED/GPIO พัง

คำนวณกระแส (ใช้ V_LED ≈ 2 V):

- LED เขียว/แดง: I = (3.3 − 2.0) / 330 ≈ **3.9 mA** (สว่างพอ และปลอดภัยต่อ GPIO ซึ่งรับได้ประมาณ 12 mA)
- LED3: I = (5 − 2.0) / 330 ≈ **9 mA**

### 5.7 ขาที่หลีกเลี่ยง (Strapping pins)

ESP32 อ่านค่าบางขาตอนเปิดเครื่อง (strapping pins) เพื่อตัดสินใจโหมดบูต ถ้าเราต่อวงจรไว้ที่ขาเหล่านี้ ค่าที่อ่านได้อาจเพี้ยนจนบูตไม่ขึ้นหรือลงเฟิร์มแวร์ไม่ได้ **บอร์ดนี้เลี่ยง GPIO0, 2, 5, 12, 15 ทั้งหมด** ขาที่ใช้ทุกตัว (16, 17, 18, 19, 22, 23, 32, 33, 34, 35, 36, 39 และ 4) ไม่ใช่ strapping pins ขา 4 ใช้กับบัซเซอร์ ซึ่งปลอดภัยเพราะทรานซิสเตอร์ไม่ดึงเส้นไว้ตอนบูต (เสถียรที่ LOW)

## 6. การทำงานของระบบ (Device API)

เฟิร์มแวร์คุยกับเซิร์ฟเวอร์ ParkQ ผ่าน HTTP ทุกอย่างใช้ `millis()` จับเวลา ไม่มี `delay()` ลูปหลักจึงไม่ค้าง (QR ยังถูกอ่านต่อเนื่องตอนไม้กั้นเปิดอยู่)

```
เซนเซอร์ IR ──(เปลี่ยนค่า หรือ ทุก 30 วิ)──► POST /api/iot/LOT02/slots
                                              body: {device_key, slots:[0/1 x4]}

ทุก 1 วิ ◄── GET /api/iot/LOT02/commands?device_key=...   ถ้ามีคำสั่ง OPEN → เปิดไม้กั้น

ผู้ใช้สแกน QR ──► POST /api/gate/LOT02/in|out/scan  body: {token}
                  ตอบ 200 + open:true → เปิดไม้กั้น 3 วิ + LED เขียว + บี๊ปสั้น
                  ไม่ผ่าน → LED แดง + บี๊ปยาว
```

| เหตุการณ์ | ความถี่ |
|---|---|
| อ่านเซนเซอร์ IR | ทุก 100 ms |
| ส่งสถานะช่องจอด (slots) | ทุกครั้งที่ค่าเปลี่ยน และอย่างน้อยทุก 30 วินาที (heartbeat) |
| ดึงคำสั่ง (commands) | ทุก 1 วินาที |
| ไม้กั้นเปิดค้าง | 3 วินาที |

ถ้า Wi-Fi หลุด ไม้กั้นจะปิดและไม่เปิดจนกว่าจะต่อกลับ (ปลอดภัยไว้ก่อน) ถ้าส่ง slots ไม่สำเร็จ จะลองใหม่ภายใน 2 วินาที

### 6.1 คำถามที่อาจารย์น่าจะถาม

**ถ: ทำไมต้องมีไดโอด D1?**
ตอบ: กันขั้วไฟกลับ ถ้าเสียบ Adapter ผิดขั้ว ไดโอดจะบล็อกไว้ วงจรไม่ไหม้ ใช้ชอตกี (1N5822) เพราะแรงดันตกคร่อมน้อย

**ถ: ทำไมไม่ใช้ SS34?**
ตอบ: SS34 เป็น SMD บัดกรีลงรูไม่ได้ บอร์ดนี้ใช้ through-hole ทั้งหมดเพื่อให้นักศึกษาบัดกรีเองได้ จึงใช้ 1N5822 ซึ่งทำหน้าที่เหมือนกัน

**ถ: C1 470 µF ไว้ทำไม?**
ตอบ: เป็นแหล่งพลังงานสำรองให้ตอนเซอร์โวออกตัว (กระแสพุ่ง) ถ้าไม่มีแรงดันตกจน ESP32 รีเซ็ต

**ถ: ทำไมไม่จ่ายไฟทั้งหมดจาก USB?**
ตอบ: USB จ่ายได้ประมาณ 500 mA ไม่พอสำหรับเซอร์โว 2 ตัว + QR 2 ตัว จึงใช้ Adapter 5 V 2 A และมี PTC ป้องกันกระแสเกิน

**ถ: ทำไมเซนเซอร์ IR ใช้ 3.3 V?**
ตอบ: ขา GPIO ของ ESP32 ทน 5 V ไม่ได้ ถ้าเซนเซอร์ใช้ 3.3 V สัญญาณ OUT จะไม่เกิน 3.3 V จึงปลอดภัย

**ถ: ทำไมใช้ GPIO34–39 กับเซนเซอร์?**
ตอบ: เป็นขา input-only ใช้รับสัญญาณอย่างเดียว ซึ่งตรงกับงานของเซนเซอร์ และเหลือขา I/O ปกติไว้ใช้กับเอาต์พุต

**ถ: R5/R6 คืออะไร ทำไมไม่ใส่?**
ตอบ: ตัวแบ่งแรงดัน 1 kΩ + 2 kΩ ทำให้ 5 V เหลือ 3.33 V ใส่เฉพาะเมื่อเครื่องอ่าน QR ส่งสัญญาณ 5 V ของที่ใช้เป็นลอจิก 3.3 V อยู่แล้วจึงไม่ใส่ (DNP)

**ถ: ทำไมต้องมีทรานซิสเตอร์กับบัซเซอร์?**
ตอบ: GPIO จ่ายกระแสไม่พอสำหรับบัซเซอร์ 5 V ทรานซิสเตอร์เป็นสวิตช์ ใช้กระแสเล็กจาก GPIO คุมกระแสใหญ่

**ถ: D2 ทำไม?**
ตอบ: flyback diode กันแรงดันย้อนจากขดลวดบัซเซอร์ตอนปิด ไม่ให้ทรานซิสเตอร์เสีย

**ถ: ทำไมตัวต้านทาน LED เป็น 330 Ω?**
ตอบ: จำกัดกระแสประมาณ 4 mA ที่ 3.3 V (และ 9 mA ที่ 5 V) พอให้ LED สว่างและไม่เกินที่ GPIO รับได้

**ถ: Strapping pin คืออะไร?**
ตอบ: ขาที่ ESP32 อ่านค่าตอนเปิดเครื่องเพื่อเลือกโหมดบูต (GPIO0, 2, 5, 12, 15) เราไม่ใช้ขาเหล่านี้ จะได้ไม่มีปัญหาบูตไม่ขึ้น

**ถ: ระบบรู้ได้อย่างไรว่าให้เปิดไม้กั้น?**
ตอบ: ผู้ใช้สแกน QR เครื่องอ่านส่งข้อความผ่าน UART ให้ ESP32 แล้ว ESP32 ส่งไปที่เซิร์ฟเวอร์ (`/scan`) ถ้าเซิร์ฟเวอร์ตอบ `open:true` ก็สั่งเซอร์โวเปิด 3 วินาที และเซิร์ฟเวอร์ยังสั่ง OPEN ผ่าน `/commands` ได้ด้วย (เช่นพนักงานกดเปิดจากหน้าเว็บ)

**ถ: ถ้าเน็ตหลุดจะเกิดอะไร?**
ตอบ: ไม้กั้นจะปิดและไม่เปิด เพราะไม่มีการตรวจสิทธิ์ ESP32 จะพยายามต่อ Wi-Fi ใหม่ทุก 5 วินาที

## 7. ลงเฟิร์มแวร์ (ESP32)

ต้องมี PlatformIO (ส่วนขยาย VS Code หรือ `pip install platformio`) โค้ดอยู่ที่ `firmware/gate-controller/` ไฟล์สำคัญ: `src/main.cpp` (โปรแกรม), `include/pins.h` (แผนผังขา ต้องตรงกับ `design.py`), `platformio.ini`

### 7.1 ตั้งค่า

1. คัดลอก `firmware/gate-controller/include/config.example.h` เป็น `config.h` (ในโฟลเดอร์เดียวกัน)
2. แก้ค่าใน `config.h`:

| ค่า | ใส่อะไร |
|---|---|
| `WIFI_SSID`, `WIFI_PASS` | ชื่อและรหัสผ่าน Wi-Fi (ESP32 ใช้ 2.4 GHz เท่านั้น) |
| `API_BASE` | `https://parkq.onrender.com` (เว็บจริง) หรือ `http://<IP-ของ-PC>:8000` ถ้ารันเซิร์ฟเวอร์ในวง LAN |
| `LOT_ID` | `"LOT02"` |
| `DEVICE_KEY` | `"dev-key-LOT02"` |

`config.h` ถูก git-ignore ไว้ ไม่ขึ้น repository

**เรื่อง LOT_ID / DEVICE_KEY:** ค่าเริ่มต้นใน `config.example.h` ตั้งเป็น `LOT02` / `dev-key-LOT02` เพราะ LOT02 เป็นลานจอดเดียวในข้อมูลตัวอย่าง (seed) ของเซิร์ฟเวอร์ที่มี device key รหัสนี้เป็นข้อมูลสาธิตที่เปิดเผยอยู่แล้วใน seed ไม่ใช่ความลับ ถ้านำไปใช้จริงต้องเปลี่ยน

### 7.2 อัปโหลดและดูผล

```
pio run -d firmware/gate-controller -t upload
pio device monitor -b 115200
```

ใน Serial Monitor จะเห็น `slots: HTTP 200` ทุกครั้งที่ส่งสถานะ และ `scan in: HTTP 200 -> OPEN` เมื่อสแกนผ่าน

ถ้าอัปโหลดไม่ได้: กดปุ่ม BOOT ค้างไว้ตอนขึ้นข้อความ "Connecting..." และถอดสายที่ต่อ GPIO ที่เกี่ยวข้องออกก่อนถ้ายังไม่ได้ทำตามหัวข้อ 5.7

### 7.3 ข้อควรรู้

- **HTTPS ใช้ `setInsecure()`** คือไม่ตรวจใบรับรอง (certificate) ของเซิร์ฟเวอร์ เหมาะกับ **เดโมเท่านั้น** ถ้าใช้งานจริงต้องฝัง CA certificate
- **เว็บ Render แบบฟรีจะหลับ (sleep)** เมื่อไม่มีคนใช้ ครั้งแรกที่เรียกจะช้า (อาจเป็นหลายสิบวินาที) และอาจ timeout ให้เปิดเว็บทิ้งไว้ก่อนสาธิต
- ตอนทดสอบเซอร์โว **ต้องเสียบ Adapter** อย่าใช้ USB อย่างเดียว

## 8. สรุปขั้นตอนทั้งหมด

1. วัดระยะแถวขา DevKit (หัวข้อ 0)
2. `python hardware/gate-controller/build_all.py`
3. Import ใน EasyEDA → ตั้ง design rules → Auto Router → Rebuild Copper → DRC (หัวข้อ 1–2)
4. สั่ง JLCPCB (หัวข้อ 3) และสั่งชิ้นส่วน (หัวข้อ 4)
5. บัดกรี ตรวจไฟก่อนเสียบ DevKit (หัวข้อ 4.6)
6. ตั้ง `config.h` และอัปโหลดเฟิร์มแวร์ (หัวข้อ 7)
7. อ่านหัวข้อ 5–6 ให้เข้าใจ เตรียมตอบอาจารย์
