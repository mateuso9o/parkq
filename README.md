# ParkQ – ระบบซื้อสิทธิ์และจองที่จอดรถออนไลน์ด้วย QR Code

ผู้ขับขี่ดูสถานะลานจอดได้แบบเรียลไทม์ ซื้อสิทธิ์จอดทันทีหรือจองล่วงหน้า แล้วใช้ตั๋ว QR สแกนเปิดไม้กั้นที่ตู้หน้าประตู
ฝั่งเจ้าของลานมีแดชบอร์ด ตั้งราคา และดูรายงานรายได้ ส่วนพนักงานหน้าลานตรวจสอบตั๋วและเปิดไม้กั้นเองได้

## วิธีรันเว็บ

```bash
pip install fastapi uvicorn qrcode
python -m uvicorn server:app --app-dir app --host 127.0.0.1 --port 8000
```

หรือดับเบิลคลิก `run_parkq.bat`

| หน้า | URL | บัญชีทดสอบ (รหัส OTP แสดงบนจอในโหมดทดสอบ) |
|---|---|---|
| แอปผู้ขับขี่ | http://127.0.0.1:8000/ | somchai@parkq.demo |
| ตู้ประตูทางเข้า / ทางออก | http://127.0.0.1:8000/gate?lot=LOT01&dir=in (หรือ `dir=out`) | – |
| ระบบหลังบ้าน (ผู้ดูแล) | http://127.0.0.1:8000/admin | admin@parkq.demo |
| พนักงานหน้าลาน | http://127.0.0.1:8000/staff | staff@parkq.demo |

- เริ่มข้อมูลใหม่ทั้งหมด: ตั้ง `PARKQ_RESET=1` ก่อนรัน
- โหมดทดสอบ (`PARKQ_DEV=1` เป็นค่าเริ่มต้น): แสดง OTP บนจอ มีปุ่มจำลองการชำระเงิน และ QR ชำระเงินเป็น QR ทดสอบที่จ่ายจริงไม่ได้
- เข้าสู่ระบบด้วย **อีเมล + รหัส OTP 6 หลัก** (บัญชีผูกกับอีเมล เบอร์โทรเป็นข้อมูลเสริม)
- **ส่งอีเมลจริง** ตั้งตัวแปรสภาพแวดล้อมของ SMTP (ฟรี เช่น Brevo หรือ Gmail + App Password): `PARKQ_SMTP_HOST`, `PARKQ_SMTP_PORT` (587), `PARKQ_SMTP_USER`, `PARKQ_SMTP_PASS`, `PARKQ_SMTP_FROM` ถ้าไม่ตั้งค่า ระบบจะแสดงรหัสบนหน้าจอ (โหมดทดสอบ) ห้ามใส่รหัสผ่านลงในไฟล์ในโปรเจกต์
- อีเมลของผู้ดูแลและพนักงานตั้งด้วย `PARKQ_ADMIN_EMAIL` และ `PARKQ_STAFF_EMAIL` (ถ้าไม่ตั้งจะเป็นอีเมลตัวอย่างที่ส่งถึงจริงไม่ได้) ใช้ร่วมกับ `PARKQ_RESET=1` ในการสร้างฐานข้อมูลใหม่ครั้งแรก
- **เก็บข้อมูลถาวร (ฐานข้อมูลคลาวด์ฟรี)** สมัคร Neon (neon.tech) เลือกภูมิภาค Singapore แล้วคัดลอก connection string ที่ขึ้นต้นด้วย `postgresql://` ไปตั้งเป็น `DATABASE_URL` (บน Render ตั้งใน Environment) ถ้าไม่ตั้ง ระบบใช้ SQLite ในเครื่องซึ่งถูกล้างทุกครั้งที่ Render รีสตาร์ท
  - ครั้งแรกให้ตั้ง `PARKQ_RESET=1` เพื่อสร้างตารางและข้อมูลตั้งต้น แล้ว **ลบตัวแปรนี้ออกทันที** (ถ้าค้างไว้ ข้อมูลจะถูกล้างทุกครั้งที่รีสตาร์ท)
  - รันเทสต์บน Postgres ในเครื่อง: `pip install -r requirements-dev.txt` แล้วตั้ง `DATABASE_URL` ชี้ไปที่ฐานข้อมูลทดสอบ
- ใช้งานจริง: ตั้ง `PARKQ_DEV=0`, `PARKQ_SECRET=<ค่าสุ่มยาว>`, `PARKQ_PROMPTPAY_ID=<เบอร์/เลขพร้อมเพย์ของร้าน>` และต่อ SMS / Payment Gateway

## บอร์ด ESP32 (Gate Controller) คุยกับระบบอย่างไร

ทุก request ใส่ `device_key` ของลาน (ดูได้ในฐานข้อมูล ตาราง `lots`)

| ทำอะไร | เรียก |
|---|---|
| ส่งสถานะช่องจอดจากเซ็นเซอร์ | `POST /api/iot/{lot}/slots` body `{"device_key": "...", "slots": [1,0,0,1]}` |
| ดึงคำสั่งเปิดไม้กั้น (ทุก 1 วินาที) | `GET /api/iot/{lot}/commands?device_key=...` → `[{"gate": "in", "command": "OPEN"}]` |
| ส่งโค้ด QR ที่เครื่องอ่านสแกนได้ | `POST /api/gate/{lot}/in/scan` หรือ `/out/scan` body `{"token": "..."}` |

ถ้าบอร์ดไม่ส่งข้อมูลเกิน 2 นาที ระบบจะแสดงลานนั้นเป็น "ข้อมูลไม่เป็นปัจจุบัน" และปิดการขายชั่วคราว

## สร้างเอกสาร W5–W9 ใหม่หลังแก้เว็บ

เปิดเซิร์ฟเวอร์ด้วยข้อมูลใหม่ (`PARKQ_RESET=1`) แล้วรัน:

```bash
python gen/capture.py      # ถ่ายภาพทุกหน้าจอจากเว็บจริง พร้อมเลขกำกับ Element
python gen/draw.py         # วาด Workflow, สถาปัตยกรรม, Screen Flow
python gen/make_docs.py    # รันเทสต์ทั้งหมด แล้วสร้างไฟล์ Word ใน ส่งงาน/
```

เนื้อหาเอกสาร (Requirement, คำอธิบายหน้าจอ, Test Case, Defect) อยู่ที่ `gen/spec_data.py` และ `gen/screens_data.py`
ถ้าเพิ่มหรือย้ายช่องบนหน้าจอ ให้แก้ลำดับ `data-el` ในหน้าเว็บกับรายการ elements ใน `screens_data.py` ให้ตรงกัน

## โครงสร้างโฟลเดอร์

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `app/` | เว็บเซิร์ฟเวอร์ FastAPI (`server.py`, `db.py`) และหน้าเว็บ (`static/`) |
| `code/` | ตรรกะหลัก `parkq_core.py` และชุดทดสอบ |
| `gen/` | สคริปต์สร้างเอกสารและข้อมูลเอกสาร |
| `ส่งงาน/` | ไฟล์ส่งอาจารย์ W5–W9 (.docx, .pdf, .xlsx) |
| `build/` | ไฟล์ชั่วคราว (ภาพ, log) ลบได้ |
