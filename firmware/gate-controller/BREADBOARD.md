# ParkQ gate: ต่อบนเบรดบอร์ด + ซ้อมเดโม (ไม่ต้องใช้ PCB และไม่ต้องมีเครื่องอ่าน QR)

> ทำตามลำดับ A → B → C ถ้าติดตรงไหน ข้ามไปใช้ "แผนสำรอง" ท้ายไฟล์ได้เลย
> คู่มือนี้เขียนจากแบบ pin map (`include/pins.h`) และของที่เห็นในรูป ยังไม่เคยทดสอบกับบอร์ดจริง ต้องอ่านค่าบนชิ้นส่วนจริงยืนยันทุกครั้ง

## 0. ก่อนเริ่ม
- **สาย micro-USB แบบส่งข้อมูล** (สายชาร์จอย่างเดียวใช้ไม่ได้) เสียบแล้ว Device Manager ต้องขึ้นพอร์ต COM (เช่น `USB-SERIAL CH340 (COM3)`)
  ถ้าขึ้นเป็นอุปกรณ์ไม่รู้จัก ติดตั้งไดรเวอร์ CH340/CP210x ตามชิปที่พิมพ์บนบอร์ด
- **Wi-Fi 2.4 GHz** ที่ไม่มีหน้า login (ใช้ฮอตสปอตมือถือได้) ESP32 ต่อ 5 GHz ไม่ได้
- ตั๋วทดสอบ: ซื้อตั๋ว LOT02 ในแอป (จำลองชำระเงิน) แล้วเตรียมมือถืออีกเครื่องไว้สแกน

## A. ทดสอบแบบไม่ต่อสายอะไรเลย (env `minimal`)
1. คัดลอก `include/config.example.h` ทับ `include/config.h` แล้ว **พิมพ์ชื่อ/รหัส Wi-Fi เอง** (ไฟล์นี้ git-ignored)
   ตั้ง `API_BASE "https://parkq.onrender.com"`, `LOT_ID "LOT02"`, `DEVICE_KEY` ตามที่ใช้ในระบบ
2. อัปโหลด: `pio run -e minimal -t upload` (ถ้าอัปโหลดไม่ผ่าน กดปุ่ม **IO0/BOOT** ค้างตอนขึ้น "Connecting..." แล้วปล่อย)
3. เปิด monitor: `pio device monitor` (115200) ต้องเห็น `Wi-Fi: connected, IP ...` และ `slots: HTTP 200`
4. กดปุ่ม **IO0** ค้าง = ช่อง 1 มีรถ → เปิด `https://parkq.onrender.com/twin?lot=LOT02` ช่อง 1 ต้องเป็นสีแดงและรถวิ่งเข้า
5. สแกนตั๋วด้วยมือถือที่ `/gate?lot=LOT02&dir=in` (ปุ่มเปิดกล้องสแกน) → monitor ต้องขึ้น `barrier in: OPEN`
   (ถ้าบอร์ดมีไฟ LED ที่ GPIO2 มันจะติด 1.5 วินาที)

## B. ต่อวงจรเต็มบนเบรดบอร์ด (อัปโหลดด้วย env `esp32dev`: `pio run -t upload`)
ตัดไฟทุกครั้งก่อนต่อ/แก้สาย (ถอด USB) และ **ห้ามป้อน 5V เข้าขา GPIO** (ESP32 ทนได้แค่ 3.3V)

| อุปกรณ์ | ขาอุปกรณ์ | ต่อกับ |
|---|---|---|
| Servo ทางเข้า (SG90) | สัญญาณ (ส้ม/เหลือง) | GPIO18 |
| | ไฟ + (แดง) | 5V (ขา VIN/5V ของบอร์ด) |
| | GND (น้ำตาล/ดำ) | GND |
| Servo ทางออก | สัญญาณ | GPIO19 (ไฟ + กับ GND เหมือนด้านบน) |
| IR ช่อง 1 / 2 / 3 / 4 | OUT | GPIO34 / 35 / 36 (VP) / 39 (VN) |
| IR ทุกตัว | VCC / GND | 3V3 / GND |
| LED เขียว | GPIO23 → ตัวต้านทาน 220–330 Ω → ขายาว (+) ของ LED, ขาสั้น (-) → GND | |
| LED แดง | GPIO22 → ตัวต้านทาน 220–330 Ω → ขายาว (+), ขาสั้น (-) → GND | |
| บัซเซอร์ (แบบ **active**) | GPIO4 → ตัวต้านทาน ~1 kΩ → ขา **Base** ของทรานซิสเตอร์ NPN | |
| | Emitter → GND, Collector → ขา (-) ของบัซเซอร์, ขา (+) ของบัซเซอร์ → 5V | |

หมายเหตุสำคัญ
- **ขาของทรานซิสเตอร์ต่างกันตามเบอร์** (เช่น BC547 = C-B-E, 2N2222/PN2222 = E-B-C) อ่านเบอร์ที่พิมพ์บนตัวและเช็กจากดาตาชีตก่อนต่อ
- **อ่านค่าตัวต้านทานด้วยแถบสี** 330 Ω = ส้ม-ส้ม-น้ำตาล, 1 kΩ = น้ำตาล-ดำ-แดง ถ้าไม่แน่ใจ ใช้มัลติมิเตอร์วัด
- บัซเซอร์ passive จะไม่ส่งเสียงบี๊บ (เฟิร์มแวร์แค่เปิด/ปิดขา) ต้องเป็น active ถ้าไม่แน่ใจ ลองต่อ 3V กับขา (+)(-) ถ้าร้องเอง = active
- **Servo ดึงกระแสสูง**: ถ้าบอร์ดรีบูตหรือ servo สั่นตอนหมุน ให้ใส่คาปาซิเตอร์ 100–470 µF คร่อมไฟ servo หรือใช้แหล่ง 5V แยก (ต่อ GND ร่วมกับบอร์ด)
- **อะแดปเตอร์หัวกลม**: อ่านแรงดันที่ฉลากก่อน ใช้ได้เฉพาะถ้าเป็น 5V ถ้าเป็น 9V/12V ห้ามต่อเข้า servo หรือขา 5V
- โมดูล IR: ขา OUT เป็น LOW เมื่อมีวัตถุอยู่หน้าเซนเซอร์ (เฟิร์มแวร์ถือว่า LOW = มีรถ) ปรับสกรูบนโมดูลถ้าไวเกินไป/ไม่ไวพอ
- ขา GPIO34-39 เป็น input อย่างเดียวและไม่มี pull-up ในตัวบอร์ด โมดูล IR ต้องขับสัญญาณเอง (โมดูลมาตรฐานทำได้)

## C. รายการทดสอบทีละข้อ (ติ๊กทีละอัน)
1. [ ] monitor: `Wi-Fi: connected` และไม่มี `HTTP -1` ติดต่อกัน 30 วินาที
2. [ ] เอามือบัง IR ช่อง 1 → `slots: HTTP 200` และช่อง 1 ใน `/twin` เป็นสีแดง
3. [ ] ซื้อตั๋ว LOT02 ใหม่ แล้วสแกนขาเข้าด้วยมือถือ → servo ทางเข้าหมุน 90°, LED เขียวติด, บัซเซอร์ดัง, ปิดเองหลัง 3 วินาที
4. [ ] สแกนขาออก (`dir=out`) → servo ทางออกหมุน
5. [ ] เอามือออก → ช่องกลับเป็นสีเขียวใน `/twin`

## D. ปัญหาที่เจอบ่อย
| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| ไม่มีพอร์ต COM | สายเป็นแบบชาร์จอย่างเดียว หรือยังไม่ได้ลงไดรเวอร์ |
| อัปโหลดค้าง "Connecting..." | กดปุ่ม IO0/BOOT ค้างแล้วลองใหม่ |
| `Wi-Fi: (re)connecting...` วนไม่จบ | รหัสผิด, เป็น Wi-Fi 5 GHz หรือมีหน้า login |
| `commands: HTTP 403` | `DEVICE_KEY` หรือ `LOT_ID` ไม่ตรงกับลานที่ตั้งไว้ |
| `HTTP -1` ต่อเนื่อง | เซิร์ฟเวอร์ Render หลับอยู่ (เปิดเว็บทิ้งไว้ 1 นาทีก่อน), Wi-Fi อ่อน หรือสัญญาณถูกบล็อก |
| Servo สั่น/บอร์ดรีบูต | ไฟ servo ไม่พอ ใส่คาปาซิเตอร์หรือแหล่ง 5V แยก |
| ช่องจอดค้างเป็น "มีรถ" | IR ไวเกิน (หมุนสกรูโมดูล) หรือสาย OUT ลอย |

## แผนสำรอง (ไม่พึ่งฮาร์ดแวร์)
- **อุปกรณ์จำลองในเบราว์เซอร์:** เปิด `https://parkq.onrender.com/device?lot=LOT02&key=<DEVICE_KEY>` กด "เริ่มทำงาน" ทำตัวเหมือนบอร์ดทุกอย่าง
  (ติดป้ายชัดเจนว่าเป็นการจำลอง) ใช้ร่วมกับ `/twin` ได้
- **Wokwi:** ซิมจับมือ HTTPS ไม่เสถียร ใช้อัดวิดีโอตอนที่ทำงาน (`barrier in: OPEN`) ไว้เป็นหลักฐานว่าเฟิร์มแวร์จริงรันได้

## ลำดับนำเสนอที่แนะนำ (ซื่อสัตย์ว่าอะไรจริง อะไรจำลอง)
1. อธิบายสถาปัตยกรรม: ESP32 ↔ REST API ↔ เว็บ (บอร์ดจริง หรือจำลองถ้าบอร์ดไม่ผ่านการทดสอบ)
2. เดโมสด: ซื้อตั๋ว → สแกนด้วยมือถือ → ไม้กั้นเปิด (บอร์ดจริง / `/device`) → `/twin` แสดงรถวิ่งเข้า
3. เอามือบังเซนเซอร์ → ช่องเปลี่ยนสี → ย้อนดูเหตุการณ์ด้วยแถบเวลา
4. บอกตรง ๆ ว่า PCB และเครื่องอ่าน QR ยังไม่มา ใช้เบรดบอร์ดและกล้องมือถือแทน
